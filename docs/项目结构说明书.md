# 项目结构说明书

> 成果提交清单里称为“系统结构说明书”，与本项目结构说明书为同一份文档。

## 1. 总体架构

系统采用前后端分离架构。前端（Vue 3 SPA，运行在 5173）通过 HTTP/JSON 调用后端（Spring Boot，运行在 8080），后端通过 MyBatis 访问 MySQL（`video_db`），并把上传的视频与封面保存在本地磁盘目录。

```text
浏览器 (Vue 3 + Vite :5173)
        │  HTTP / JSON（axios，Bearer Token）
        ▼
Spring Boot 应用 (:8080)
  Filter(TraceId/日志) → Interceptor(AuthInterceptor) → Controller → Service → Mapper
        │                                   │
        │ Caffeine 缓存（Spring Cache）      │ 本地磁盘 uploads/ 与 uploads/covers/
        ▼                                   ▼
      MySQL 8（video_db）
```

## 2. 后端分层与包结构

后端包名 `pre.wc.mediamanager`，按职责分层：

| 包 | 职责 |
| --- | --- |
| `controller` | 接收 HTTP 请求、参数校验、返回统一结果 |
| `service` / `service.impl` | 业务逻辑（上传、分页、删除、点赞、鉴权等） |
| `mapper` | MyBatis 数据访问接口（配合 resources/mapper/*.xml） |
| `entity` / `pojo.dto` | 数据库实体与传输对象（DTO/VO） |
| `config` | Web、CORS、缓存、全局异常、密码编码器、上传属性、日志过滤器 |
| `security` | JWT 令牌、拦截器、用户上下文、登录限流、traceId |
| `cache` | 缓存日志装饰器（记录 CACHE HIT/MISS/PUT） |
| `common` | 统一结果 `Result`、分页 `PageResult`、业务/鉴权异常 |
| `auth.dto` | 登录、注册、用户 VO 等认证对象 |
| `util` | 视频元数据解析（读取时长） |

## 4. 请求处理流程

1. 请求进入 `TraceIdFilter`：生成或复用 `X-Request-Id`，写入 MDC 的 `traceId`。
2. `AuthInterceptor.preHandle`：若带 `Authorization: Bearer <token>` 则解析 JWT、校验用户状态并写入 `UserContext`；对非公开接口且未登录的请求抛出 401。
3. `Controller` 接收请求并调用 `Service`。
4. `Service` 执行业务逻辑，期间可能读写 Caffeine 缓存，并通过 `Mapper` 访问数据库。
5. 返回 `Result<T>`（统一结构）；异常由 `GlobalExceptionHandler` 统一转换。
6. 请求结束时 `TraceIdFilter` 输出汇总日志，`AuthInterceptor.afterCompletion` 清理 `UserContext`。

公开接口（无需登录）：登录、注册、分页、详情、分类、热门、视频流播放、封面读取、播放计数。

## 5. 缓存设计

采用 Spring Cache + Caffeine，TTL 5 分钟，最大 2000 条，并接入统计。缓存名与失效策略：

| 缓存名 | 内容 | 失效时机 |
| --- | --- | --- |
| `videoPage` | 分页查询结果 | 上传、删除、点赞、换封面 |
| `videoDetail` | 视频详情 | 删除、点赞、播放、换封面 |
| `videoCategories` | 分类列表 | 上传、删除 |
| `videoHot` | 热门榜 | 上传、删除、点赞、播放、换封面 |

播放是高频写操作，只失效 `videoHot` 与 `videoDetail`，避免频繁清空分页缓存。缓存命中会输出 `CACHE HIT/MISS/PUT` 日志。

## 6. 日志与链路追踪

- 每个请求带 `X-Request-Id`，响应头返回 `X-Request-Id` 与 `X-Response-Time`。
- 日志分文件滚动：`app.log`（全量/SQL）、`error.log`（系统异常）、`business.log`（业务事件）、`security.log`（登录/鉴权/限流）。
- MDC 中 `traceId` 与 `userId` 贯穿 Controller、Service、Mapper 与缓存日志，便于定位一次请求的完整链路。
